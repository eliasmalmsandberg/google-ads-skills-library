1. **Source**: Kirk Williams, ZATO, "Video: How to Create (and Use) a Supplemental Source in Google Merchant Center Next", https://zatomarketing.com/blog/how-to-create-a-supplemental-source-in-google-merchant-center-next · **Tier**: 1 · **Date**: 2024-10-31 (updated 2026-04-17) · **Claim**: Supplemental sources are off by default in Merchant Center Next; enable "Advanced Data Source Management" under Add-ons. Build from the Google Sheets template; schedule the pull one hour after the primary feed loads; run a manual update the first time; rename the source for the attribute it edits. `id` matching is case-sensitive — zero matches usually means case (Shopify IDs copied from Google Ads reporting in lowercase). Include only the attributes you intend to change: everything in the supplemental source is hard-coded over the primary, so importing 500 attributes to change 3 locks the other 497 against future primary updates. Use cases: can't change the primary quickly; emergency price correction during a suspension (fix via supplemental → Google re-verifies → lift → then fix primary); custom labels for promo/clearance segmentation by swapping IDs in the sheet. Never delete a supplemental source — disassociate it from the primary's rules so it can be reattached. Default principle: change the primary source whenever you can, because layered sources make problems hard to diagnose. Data layering order he describes: Content API / feed → supplemental source → feed (attribute) rules → Google's automated improvements → manual product edits. · **Evidence or opinion**: Worked procedure from client accounts; no performance data.

## Dissenting view
Holly Kelly (PPC Hero, 2025-07-02, https://ppchero.com/how-to-maximize-shopping-ad-visibility-with-feed-optimization/) says manual Merchant Center edits to price or stock should be avoided because they override automated updates and create inconsistency. Williams uses a supplemental source to force a price fix during a suspension and then repairs the primary. The disagreement is about whether an override layer is ever the right tool for price/availability: both agree it must be temporary and that the primary feed should carry the truth. (Kelly is not canon; cited only as the dissent.)

## What the platform currently does [Google docs]
- "Feed rules" are now "attribute rules" and need the "Advanced data source management" add-on. Data-source operations: Set to, Set to multiple, Extract, Take latest. Modification operations: Prepend, Append, Add repeated field, Optimize URL, Find & Replace, Calculate, Split & Choose, Clear. Conditions use AND/OR. Rules are saved as draft, previewed/tested, then applied. [Google docs, undated]
- Custom attributes (marked `*` in "Processed attributes") can hold a value for later use in another attribute's rule — e.g. keep `burgundy` in `color` while writing "red" into the title. [Google docs, undated]
- Automatic item updates (price, sale price, availability, condition) are on by default and read schema.org markup, falling back to extractors; on a detected mismatch the product may be disapproved rather than updated, especially where price/availability changes more than once a day; updates may stop if mismatches become too numerous; don't enable price automation where pages show multiple strikethrough prices. [Google docs, undated]
- Merchant Center `custom_label` values take 24–48 hours to reach Google Ads. [Google docs, Google Ads Help]
- I could not fetch Google's supplemental-sources help page (7450276/7450282 errored); the precedence order is taken from Williams (source 1), not from Google.
