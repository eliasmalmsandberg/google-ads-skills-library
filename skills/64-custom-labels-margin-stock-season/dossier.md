## Sources

(b) For bidding, start with a handful of margin levels holding roughly equal numbers of products, because labels with few products never collect enough data; refine later. Illustrative tiers: 0–20% margin $1.00, 20–40% $2.00, 40%+ $3.00, then item-level bids inside a tier where data allows. (c) New label values do not rebuild product groups — items fall into "Everything else"; Optmyzr runs a script tracking the share of clicks from "Everything else". (d) Priority campaigns containing only labelled products (best sellers, clearance, overstock) serve first regardless of bid. · **Evidence or opinion**: Method from Optmyzr's own accounts plus Reinhard Einwagner (Whoop!) webinar material; no quantified lift. ## Dissenting view
Kirk Williams (ZATO, "DTC brand with 100K+ SKUs…", 2026-04-09, https://zatomarketing.com/blog/dtc-brand-with-100k-skus-but-stalled-growth-in-google-shopping-or-pmax-try-these-ideas-for-growth) warns that "Zombie" campaigns built from low-volume labels often just cannibalise the main campaign and that PMax may already be correctly deprioritising those SKUs; only run one if the audience/query/product cluster is genuinely different. Nils Rooijmans (2022) and the Optmyzr Smart Product Labeler framing (Heroes/Sidekicks/Villains/Zombies/Flukes, https://help.optmyzr.com/en/articles/10373106-about-smart-product-labeler) treat a separate zombie campaign as a standard play. The disagreement is about whether low-volume products are starved by the algorithm (fixable with a campaign) or correctly ignored (not worth the spend).

## What the platform currently does [Google docs]
- Five labels, `custom_label_0`–`4`; one value per label per product; 1–100 characters; up to 1,000 unique values per label and 5,000 across all five, account-wide; values beyond the cap are ignored for bidding and reporting. [Google docs, Merchant Center spec, undated]
- Labels apply to Shopping, Performance Max and Demand Gen product groups ("listing groups"); shoppers never see them. New/edited labels take 24–48 hours to appear in Google Ads; sync can fail near the Merchant Center attribute limit. [Google docs, Google Ads Help, undated]
- Google's own example labels: season, selling rate (BestSeller/LowSeller), clearance, margin (Low/High), release year. Google describes use for product groups within a campaign; it does not recommend splitting campaigns by label. [Google docs]
- Feed rules were renamed "attribute rules" and require the "Advanced data source management" add-on in Merchant Center Next; supplemental data sources still exist for adding attributes keyed on `id`. [Google docs, https://support.google.com/merchants/answer/14994083, undated]

## Baseline check
Read `google-ads-audit-ecommerce` (Layer 3 and Layer 4: "custom labels used: margin tier, bestseller, seasonal" as a checkbox; break-even ROAS = 1/margin; star/core/drain/dead tiers by ROAS). The baseline says *that* you should label by margin and tier products; it has no rule for how many tiers, how to assign products to tiers, how to keep labels fresh, which label dimension to start with, how to avoid the "Everything else" leak, or when a low-volume campaign is a mistake. This skill supplies those decision rules and the cost×ROAS bucket logic practitioners actually run.

## Judgment calls
- Treated the Optmyzr 2025 piece as Tier 1 method even though it is Optmyzr content: the rules are explicit and tool-agnostic; I excluded the tool-promotional parts.
- Added smec/Einwagner as Tier 2 for *this topic only* (label-as-experiment and the historicisation fact). It is a tool vendor but the article is method, not pitch.
- Mike Rhodes' bucket thresholds are user-configurable and the docs don't publish defaults; the skill therefore states the two-axis logic and tells the operator to set thresholds from break-even ROAS, rather than inventing default numbers.
- The row says "One-off"; the sources say labels must be refreshed nightly (Optmyzr) / daily (Rhodes) / hourly if dynamic (smec). The skill treats the *design* as one-off and the *refresh* as an automated cadence.
