## Dissenting view
Google's position is that QS "should not be optimised or aggregated with the rest of your data" [Google docs] — a daily, aggregated, impression-weighted tracker is exactly that. Within the canon, Hopkins argues for spending less attention on QS and more on quality itself (Optmyzr PPC Town Hall, 2020); the disagreement is whether a daily snapshot is a monitoring necessity or a vanity series. Vallaeys's 2015 incident is the strongest argument for the tracker: without history you cannot tell a reporting bug from a real drop.

## What the platform currently does [Google docs]
- [Google docs] Historical columns "Qual. Score (hist.)", "Landing Page Exper. (hist.)", "Ad Relevance (hist.)", "Exp. CTR (hist.)" exist in the keyword report; segment by day to see end-of-day values; data back to 22 Jan 2016 (SEL/Marvin, 15 May 2017; Google help answer/6167118). So "Google doesn't keep QS history" is no longer literally true: Google keeps end-of-day keyword-level history, but no aggregate, no weighting, no charting, and nothing for removed keywords.
- [Google docs] Null QS ("—") for keywords without enough exact-match impressions/clicks since the week of 12 Sep 2016; Scripts `Keyword.getQualityScore()` returns NULL for them; API `HasQualityScore = FALSE` filter; numeric QS filters silently exclude nulls (Ads Developers blog, 15 Aug 2016; Scripts reference AdsApp.Keyword, fetched 2026-10-13).
- [Google docs] Scripts `getQualityScore()` returns int 1–10; the Scripts object model exposes no component methods — components come via the report/GAQL path (`ad_group_criterion.quality_info.quality_score`, `.creative_quality_score`, `.post_click_quality_score`, `.search_predicted_ctr`) (Google Ads API reference, AdGroupCriterion.QualityInfo; Scripts reference).
- [Google docs] Google states QS is not a KPI and should not be aggregated (answer/6167118).

## Baseline check
Read `google-ads-scripts` (its QS tracker example) and `google-ads-quality-score`. The baseline script logs keyword QS to a sheet weekly with a 100-impression filter and a "<5 = LOW" flag — a raw dump. This skill adds the snapshot design from the canon: daily cadence, impression-weighted aggregate line, component distribution and 1–3 component index, null handling, a drop-alert rule, removed-keyword retention, and the Vallaeys bug-vs-real test.

## Judgment calls
- Wesley Parker added as Tier 2 for this topic: full script and method published on SEL; no evidence he contradicts Google, so flagged as a topic-only addition.
- PPC.io is not canon; its thresholds (100 impressions, drop ≥2) are not used as rules — the 100-impression filter also appears in the baseline, and the skill's thresholds come from Optmyzr (QS < 6, cost > 0) and Vallaeys (±0.2 normal, 2-point = investigate).
- The row's premise ("QS history, which Google doesn't keep") is corrected in the skill: Google keeps keyword-level end-of-day history; the script's value is aggregate, weighted, chartable, and bug-detectable history.
- No canon script was fetchable in full (Brainlabs site unreachable), so the skill specifies the design, not code.

## Canon strength: Strong
Brainlabs (script), Optmyzr (tooling method, two help pages + two Vallaeys posts), Rooijmans (review and cadence), Parker (Tier 2 script).

## Invalidated by
Removal of `quality_info` from the Google Ads API/Scripts reports, a change to Scripts' 30-minute execution limit, or Google shipping native QS trend charts with impression weighting.
